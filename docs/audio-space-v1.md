# 声音空间 V1：让耳朵知道东西在哪（2026-10-31）

按"开放世界 + 俯视角 + 永久死亡"这个基调重排声音。这轮只做声音，不动玩法规则。

## 1. 之前是什么状态

`audio-feedback-v1.md` 那轮把音效从"没有"做到"有"：八种原创合成短音、固定播放器池、按真实移动距离触发脚步、M 静音。但它有一个结构性问题：

- **全局等音量**。所有音效都走 `AudioStreamPlayer`，`volume_db` 是配置里的常数。10 米外开的门和耳边开的门一样响，40 米外的僵尸和贴脸的僵尸一样吵。
- **僵尸没有声音**。`c1-threats.md` 当时就写了"尚无真正可听音效"；后来补的全是玩家自己的动作声。AI 侧有噪声事件，玩家侧听不见，于是"听声辨位"这件事根本不存在。
- 在永久死亡的基调下，这是最要命的缺口：你看不见的地方必须能**听见**，否则死亡只会来得莫名其妙。

## 2. 空间模型

新文件 `godot/scripts/audio_space.gd`，全部是纯函数，不碰节点、不碰音频设备。参数集中在 `data/audio.json` 的 `space` 块：

| 参数 | 值 | 含义 |
| --- | --- | --- |
| `reference_distance` | 3.0 m | 这个距离以内满音量（自己的脚步、手里的门） |
| `rolloff_db` | 7.0 dB | 距离每翻一倍衰减 7 dB |
| `max_distance` | 42.0 m | 超过这个距离**根本不调度播放** |
| `floor_gap` | 1.5 m | 高度差超过它才算"隔了一层" |
| `floor_penalty_db` | −12 dB | 隔层的额外扣减（楼板吃掉高频） |
| `floor_db` | −34 dB | 增益地板，避免远处变成听不见的嘶声 |

于是听感是线性的、可预测的：

| 距离 | 增益 |
| --- | --- |
| 0–3 m | 0 dB |
| 6 m | −7 dB |
| 12 m | −14 dB |
| 24 m | −21 dB |
| 42 m | 静音（不调度） |
| 楼上/楼下（同平面 2 m） | −12 dB |

### 为什么不用引擎的 3D 衰减

`AudioStreamPlayer3D` 自带距离衰减，但它的距离量的是**到 listen 的三维距离**。这套游戏是正交俯视，相机吊在 20 米高空，于是：

- 脚边的声音距离 ≈ 20 m，远处 40 m 的声音距离 ≈ 45 m；
- 两者只差 5 dB，动态范围被相机高度整个吃掉，听起来全都一样远。

所以这里把衰减模型关掉（`ATTENUATION_DISABLED`），用**平面距离 + 楼层差**自己算 `volume_db`；`AudioStreamPlayer3D` 只负责它唯一做得对的事——**左右声像**。相机水平移动不影响声像，因为它跟着玩家转的是位置不是朝向。

## 3. 新增的四种声音

| id | 时长 | 用途 |
| --- | --- | --- |
| `growl` | 1.05 s | 僵尸第一次看见你（62 Hz 基频 + 3.4 Hz 颤动 + 噪声带） |
| `snarl` | 0.34 s | 挨打、抓到人（96 Hz，快速颤音） |
| `death` | 0.70 s | 倒下（基频随时间下沉 40%） |
| `glass` | 0.50 s | **预留**：破窗。玩法侧还没有破窗，先把声音备好 |

`growl` 的颤动不是为了好听，是为了**不像发动机**：纯低频正弦持续一秒会读成"怠速"，加上 3.4 Hz 的基频摆动和噪声带才有喉咙感。

## 4. 僵尸什么时候说话

三个时机，都在 `zombie.gd` 里：

1. **第一次看见你**（`mode` 从非 chase 切到 chase）——这是唯一一声"它发现你了"；
2. **打中你**（`damage_player` 之后）；
3. **被击中**（`snarl`）／**倒下**（`death`）。

两条纪律：

- **单向**。`voice()` 只调用 `game.zombie_voice()`，永远不写 `model.noise()`。所以僵尸吼叫不会唤醒同伴——否则 24 只僵尸会靠互相听见对方而永久自激。
- **每个身体限流 2.6 秒**，而且**只有真的播出声音才记冷却**。远处那只吼了但你没听见，不该浪费它下一次开口的机会。

## 5. 验收

```powershell
& 'D:\GameDev\Godot_v4.7.2-stable_win64.exe' --headless --path godot --script res://tests/test_audio_space.gd
& 'D:\GameDev\Godot_v4.7.2-stable_win64.exe' --path godot --script res://tests/test_game_audio.gd
```

`AUDIO_SPACE_OK`（无头，纯数学 + 节点行为）：

- 3 m 内 0 dB，6/12/24 m 分别 −7/−14/−21 dB，距离再远音量不回升（逐米采样 40 次）；
- 42 m 整静音，41.9 m 可听，负数/NaN/∞ 全部拒绝；
- 隔层 2 m 扣 12 dB，同一个楼梯台阶（0.4 m）不扣；
- 脏配置（负参考距离、字符串半径、999 dB 衰减、正数楼层惩罚）全部回退或夹紧，不会算出 NaN 增益；
- 8 m 实测 −9.9 dB（3 m 参考的 2.67 倍 = 1.42 个翻倍）；
- 近处 2 m 满音量、100 m 不调度且不计数、静音时不调度也不计数；
- 同一声源 2.6 s 内第二声被拒，换一只僵尸立刻可以吼；远处被拒的那声不消耗冷却；读档后重新武装；
- 连续 60 次播放，池子不增长、游标不越界；
- **播放不产生 AI 噪声**：播枪声、吼叫、死亡声之后 `state.noises` 长度不变，也不会凭空多出僵尸；
- 读档后 `sync` 不重播历史；
- `fired` / `door` 事件仍然照旧出声。

`GAME_AUDIO_OK`（真实窗口内）新增三条端到端断言：僵尸看见玩家会 `growl`、木棍打中会 `snarl`、打倒会 `death`。它同时保留了原来的"实际开关门/走动/搜刮/近战/开枪/受伤各触发一次、读档不重播、静音不改变感知状态"。

## 6. 已知边界

- **玩家自己的脚步仍然没有位置**（`play_effect` 固定在听者身上，这是对的），但**别人**的脚步没有：僵尸走路不发声，只有吼叫。要做到"听见走廊里的脚步"，需要给移动加脚步节流，这轮没做。
- 枪声没有室内混响和距离混响差异；贴着墙开枪和站在街上开枪目前只有音量差别。
- 破窗、发电机、雨声的**玩法**还没有，`glass` 只是把声音先备好。
- 听感（rolloff 7 dB 是不是太陡、growl 是不是太吵）必须人耳决定。参数全在 `audio.json`，改完跑 `AUDIO_SPACE_OK` 就能确认曲线没走形。
- 网页版（E1）用的是同一套音频节点，`AudioStreamPlayer3D` 在 Web 下走 WebAudio，本轮没有在浏览器里复核听感。
