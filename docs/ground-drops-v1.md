# 落地物资与分批搬运 V1

本轮沿用现有街区、背包、容器和存档，不新增免费物资。背包按 **I**，选择“放下1件”；靠近落地物资按 **E** 拾回，或按 **B** 逐件存取。负重上限仍生效，可以先卸货再分批搬运。

## 数据与约束

- `ground_drops.gd`负责交易与校验；`ground_drops_visual.gd`负责显示，规则集中在`rules.json`。
- 每次仅转移一件现有物品；最多64处落地点，每处10kg，同室且相距不超过0.35m合并。失败不扣物品。空地点复用ID，避免删除日志引用。
- 保存位置、所属房间、容器库存和递增序号。旧档没有这两个字段时，在内存添加空记录，不修改原文件、不补库存。
- 弹匣装有子弹或正在装填的手枪禁止放下，先完成装填并按U卸弹；最后一把已装备武器放下后切回拳头。
- 新事件`dropped`记录真实放下动作；`recovered`区别于首次世界搜刮，避免反复取放刷每日搜刮统计。
- 地面容器沿用距离与墙体/门射线检查，不允许隔墙拾取。清空后显示消失，正在打开的存取面板仍可放回物品。

## 真实验证

规则测试`GROUND_DROPS_OK`：真实初始库存、100次取放的物品守恒、负重变化、占用地点存读档、非法位置/孤立容器/超重数据拒绝、旧档兼容、有限枪弹与装备状态，以及容量/数量上限失败保护与相邻合并。

实机测试`GROUND_DROP_PLAYTHROUGH_OK`：实际移动进屋、搜刮、出屋，通过正式背包按钮放下饮水，保存继续，走远再回来，通过正式存取界面取出/放回，E拾回，空地点再次存读档不重生。使用独立`user://tests`目录；本路线关闭敌人以单独验证交互，不能作为自然战斗证据。完整回归`ALL_CHECKS_OK`，Blender资产重跑与Godot导入通过；标准实机流程`VISUAL_SLICE_V1_OK`，3个受保护存档/导出文件指纹不变。没有为本功能另行宣称帧率提升；同轮标准采样的条件与限制仍见视觉切片报告。

```powershell
python tools/run_checks.py --godot D:\GameDev\Godot_v4.7.2-stable_win64.exe --blender D:\Blender\blender.exe --visual
```

单项入口为`godot/tests/test_ground_drops.gd`、`test_ground_drop_playthrough.gd`。四张1920×1080实机截图为`work/visual-slice/drops-01-backpack.png`至`drops-04-recovered.png`，条件见同目录`drops-capture-conditions.json`。

## 限制与后续

显示暂复用现有小木箱GLB，属于功能标记，没有新增掉落物专用美术。仅支持当前平地街区，不是多层建筑落点系统；没有物理抛掷、逐件模型、腐败、僵尸搬运或自动清理。64处上限和10kg承重是集中可调的初始保护值。

现有资产可复用：本功能直接沿用既有GLB、共享PBR与容器UI，不需要重做模型。独立项目可使用素材库导出流程，但仍须遵循资产授权台账；角色动作与玩法脚本依赖本项目规则，不能直接视为通用插件。
