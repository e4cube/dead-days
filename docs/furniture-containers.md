# 家具独立库存：住宅冰箱

2026-10-22。本轮将现有 Blender 冰箱从纯陈设接入真实库存，没有替换模型或重复建立资产管线。

## 实现与操作

rules.json 的 containers 定义ID、名称、所属建筑、局部坐标、对应碰撞体和初始物资。home_fridge 初始有1份罐头、2份饮用水，独立于住宅原柜子；使用已有 food/water 的效果和重量规则。物品转移统一通过 Survival.loot，按物品顺序拿到负重上限，剩余物资留在容器。

从正门进入住宅，沿中央走道到厨房后部，靠近冰箱按 E。提示显示具体容器名称和真实剩余数量。使用1/2/3物品腾出负重后可以继续拿取；空容器不会重复生成物品或日志。原始住宅柜子仍有原来的木棍、罐头和饮水。

世界交互检查距离、所属建筑与实体视线；射线只忽略目标容器自身的碰撞，隔墙和其他家具仍能阻挡。其他建筑柜子同样采用此检查。库存模型不负责物理视线，模型的单元测试可直接进行库存事务；实际玩家只能经场景交互。

自动日志记录真实 container、building 和 items，原有每日总结继续按实际转移数量累计。冰箱没有电力、温度、食物腐败或开门动画；当前是搜刮交互，不能存入或选择单件物品。

## 存档保护

新快照 schema4。读取schema1/2/3时沿已有迁移流程，在内存补入缺失家具库存，保留柜子、背包、敌人、时钟、灯光与其他状态，不改写旧文件。新版本保存后必须包含家具库存；缺失、负数、未知容器或非法物品时拒绝并按已有快照回退机制处理。保存后已搜空冰箱不会在重载时补货。

## 验证

test_containers.gd 验证满包不转移、有限库存、与柜子隔离、真实事件、schema4精确往返、非法库存拒绝、schema3迁移原字节不变，以及迁移后保存读取不补货。

住宅图形试玩使用真实输入进入卧室和厨房，验证隔墙射线、冰箱目标识别、超重剩余1份饮水、保存继续仍保留剩余量、使用饮水后继续取走，以及重复搜空不复制物品。额外输出 house-fridge-partial.png。没有把角色传送到冰箱前。
