# 存档可靠性 v1（多槽 / 快照轮转 / 手动备份）

单机游戏丢档是最伤的事，比少一个功能严重得多。这一轮不动玩法，只把「存档」这件事做扎实：三个存档槽、旧快照自动清理、手动备份与导出。

## 一、为什么是快照，而不是一个存档文件

原有设计已经是**不可变快照**：每次保存写一个新文件 `save_<20位微秒>_<10位计时>.json`，从不覆盖旧文件，读档时从新到旧挑第一个能通过校验的。好处是写坏了、写了一半、文件破损都不会毁掉上一份可用进度。

这一轮保留这个性质，只在外面加两层：

- **槽（slot）**：三个互不相干的快照目录。
- **轮转（trim）**：每个槽只保留最新 8 份，超出的旧快照在保存成功后删掉。

## 二、三个槽怎么落到磁盘

| 槽 | 目录 | 说明 |
| --- | --- | --- |
| 1 | `user://saves` | **保持历史路径不变**，老存档原地继续可读，不做迁移 |
| 2 | `user://saves/slot_2` | 新建 |
| 3 | `user://saves/slot_3` | 新建 |

槽 1 不搬家是刻意的：迁移代码最容易把玩家进度搬丢，而「不搬」就没有丢的风险。`user://saves` 下的子目录不会被当成快照（`DirAccess.get_files()` 不返回目录，且文件名还要过一遍格式校验）。

## 三、轮转规则（`save_store.gd`）

- 只在**保存成功之后**执行，失败的保存一个文件都不会删。
- 只处理匹配 `save_<纯数字>_<纯数字>.json` 的文件。`notes.txt`、`save_bad.json`、`save_1_2_3.json`、`backup_*.json` 一律不碰——测试里专门造了这四种文件盯着。
- 按文件名排序即时间序（数字零填充），删除下标 ≥ `keep` 的，最新的一份永远在 `[0]`。
- `keep` 默认 8，可按 store 实例调整（测试用 1 或 3 来压缩断言成本）。
- `last_trimmed` 记录上一次实际删掉几个，便于上层提示。

## 四、界面

主菜单（开局与 Esc 都回到这里）：

```
DEAD DAYS / 末日生存日志
新游戏（保留所有已有快照）
继续最近（自动选最新存档）
▸ 存档 1 · 第1天 08:05 · 生命88 · 3件
  存档 2 · 空槽
  存档 3 · 空槽
画质：…
退出
```

- 槽位那一行读的是**磁盘上最新的那份快照**，不需要先读档就能看到天数、时刻、生命和携带件数；`▸` 标出当前槽。
- 「继续最近」跨三个槽比较快照名（零填充所以字符串序即时间序），自动选最新那份。
- 日志面板（J）里多了两个按钮：**备份存档**、**导出存档**，与原有的「导出 Markdown」并排。

一个必要的边界：如果当前 `store` 被人为换到别的目录（测试、工具脚本），「继续最近」**不会**跑到槽系统里读玩家真实存档，而是老老实实读当前 store。规则是「当前 store 不属于槽系统就只管它自己」，`continue_newest()` 里三行代码。

## 五、备份与导出

- **备份**：写到 `<槽目录>/backups/backup_<20位微秒>_<10位计时>.json`。它在轮转范围之外，所以快照被删到只剩 8 份时备份还在。菜单/日志面板会显示备份数。
- **恢复备份**：`restore_backup()` 只接受 `backup_` 前缀 + `.json` 的文件，且过 `model.valid()`，不会把快照文件或半截 JSON 当备份读进来。
- **导出**：桌面版写 `user://exports/dead-days-slot<N>_<unix秒>.json` 并把绝对路径显示在提示栏；同一秒内连续导出会加 `-1`、`-2` 后缀，不会互相覆盖。Web 版走 `JavaScriptBridge.download_buffer` 触发浏览器下载。用的是**当前内存里的状态**，不是磁盘上最新的那份，所以「导出」总是导出你眼前这一刻。导出目录本身可覆盖（`export_root`），测试专用。

## 六、验收（`SAVE_SLOTS_OK`）

`godot/tests/test_save_slots_v1.gd`，九组断言（第 8 组守卫、第 9 组导出隔离）：

1. **路径**：槽 1 是 `user://saves`；槽 2/3 在子目录；非法槽号被夹到槽 1；root 可覆盖（测试用临时目录，绝不碰玩家存档）。
2. **隔离**：存槽 2 不影响槽 1/3 的文件数；空槽拒绝读档并给出「没有可用存档」；读档失败时 model 保持原样。
3. **轮转**：`keep=3` 连存 6 次后正好剩 3 份，最新那份仍在，读回来的是第 6 次的状态，没有 `.tmp` 残留，`last_trimmed == 1`。
4. **轮转不误删**：`keep=1` 时那四个「像但不该删」的文件全部存活。
5. **摘要**：空槽 `present=false`、标签是「存档 1 · 空槽」；有存档时天数/时刻/生命/件数/快照数都对，标签渲染成「第1天 08:05 · 生命88」。
6. **跨槽选最新**：槽 3 有旧快照、槽 1 有新快照时选槽 1，且选出来的那份真的能读、能过校验。
7. **备份**：备份文件存在且被列出，不计入快照数，摘要里的备份数正确，恢复后生命回到备份时的值；快照文件不能当备份恢复；不存在的备份被拒。
8. **守卫**：非法状态既不能保存也不能备份/导出，失败时不留下任何文件，并且给出明确的拒绝原因。
9. **导出不污染玩家目录**：导出目标目录可覆盖，测试写在 `user://tests/...` 下；同一秒两次导出得到两个不同的文件，且都留在配置的目录里。

## 七、已知边界

- 槽位选择**不跨启动记忆**：每次启动默认在槽 1，靠菜单里的槽位摘要去挑。做成持久化需要一个设置文件，暂未做。
- 「新游戏」只重置内存状态，不立刻写盘；按下 F5 或 Esc 才会在当前槽产生新快照。这保持了原有「不留空档」的语义。
- 没有「删除某个槽」的入口：轮转会自然收敛到 8 份，删档属于不可逆操作，宁可不给。
- Web 端的 `localStorage` 仍然只保存**当前槽**的一份副本（键里带目录名），槽间互不覆盖。
