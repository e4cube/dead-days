# 小目标 V1：从存档里读出来的四个目标

第六关「日志与持续游玩验收」的玩法增量。日志、每日总结与 Markdown 导出在第一关就已经能用，真正缺的是**给玩家一个下一步做什么的理由**。这里不写剧情任务，也不发奖励，只把玩家本来就在做的四件事变成可见的进度。

## 一、设计口径

三条硬约束，都来自路线图：

1. **基于真实状态。** 目标的进度全部从存档里已有的数据算出来——据点容器里有什么、玩家走过的最远距离、哪些工事已经完工。没有独立的"任务进度"字段，也就不存在"任务系统认为你做了但世界没变"的情况。
2. **不伪造剧情。** 没有 NPC 派活、没有连锁任务、没有过场。目标名与描述只说一件事：去干什么。
3. **不给无限奖励。** 完成一个目标**只写一条日志**（`goal_done`，心情「希望」），不发物资、不给属性、不刷新库存。它的价值是"记录我做成了什么"，不是"换了什么"。

## 二、四个目标

数据在 `data/goals.json`：

| id | 名称 | 判定 | 说明 |
| --- | --- | --- | --- |
| `stock_water` | 储备饮水 | `stock` | 据点容器里饮用水 ≥ 5 份 |
| `bring_medicine` | 带回医疗 | `stock` | 据点容器里绷带 ≥ 2 份 |
| `long_trip` | 远途探索 | `distance` | 记录的离家最远距离 ≥ 55m |
| `seal_yard` | 封住院子 | `site` | 别墅院子门 `villa_gate` 已完工 |

三类判定的口径：

- **`stock`**：只统计**属于当前据点**的容器。`container_building(id) == base_id()` 才算；落地物资（`ground_drops`）一律不计——把东西扔在院子里不叫储备。据点换到别墅后，同一个目标自动改算别墅的柜子与冰箱。
- **`distance`**：`state.goals.farthest` 单调递增，每次时间推进采样一次玩家位置到**据点中心**的距离，取历史最大值。回家不会把记录退回去，走不到的近路也不算数。
- **`site`**：直接读 `site_done()`，与别墅工事共用同一个标记，不存在第二份进度。

数值不是随手拍的：

- 住宅柜子（1 份水）+ 住宅冰箱（2 份水）初始一共 3 份，所以「储备饮水」定 5 份——玩家至少要再搬 2 份回来，目标才有意义。定 3 份会一开局就自动完成。
- 住宅内没有初始绷带，「带回医疗」定 2 份就是纯外勤任务。
- 里程碑口到市集中心约 76m、到工厂更远，55m 的门槛保证「远途探索」必须真的离开街区。
- `seal_yard` 挂在当前主线内容上，做完别墅工事的玩家顺手就会拿到。

## 三、状态与存档

存档升为 **schema 7**，只增加一块：

```json
"goals": { "done": ["stock_water"], "farthest": 76.4, "checked_at": 1439.5 }
```

- `done`：已报告的目标 id，按完成顺序。已完成的目标**永远保留在列表里**，日志面板也会继续显示为「[完成]」，不做成勾完就消失的待办清单。
- `farthest`：历史最远距离（米）。
- `checked_at`：上次判定的绝对分钟数，用于节流（见下）。

`valid()` 校验：`goals` 必须是字典；`done` 里每个 id 必须能在 `goals.json` 里找到且不重复；`farthest` 在 0…1000 之间；`checked_at` 不晚于当前游戏时间。伪造一条"已完成"的条目会被直接拒绝。

schema 6 → 7 迁移沿用前几关的规则：**按字段存在与否补，不按版本号补**。一个 schema 6 的存档补上空的 `goals`；一个已经写着 schema 7 但没有 `goals` 的快照会被 `valid()` 拒绝，`restore()` 时补齐。

## 四、判定时机与节流

`advance_time()` 每帧都会调用 `Goals.check()`：

- 距离采样**每次调用都做**（只是两个浮点减法），否则快速跑过去的一段路会被漏掉。
- 目标判定**节流到每 1 游戏分钟一次**。存取物资、装门这类操作都可能在不改变时钟的情况下连续发生，不节流就会重复写日志。

节流的后果是"存完东西可能最多 1 秒后才看到完成提示"（`minutes_per_second = 2.0`，1 游戏分钟≈0.5 秒实时）。这个延迟换来的是一条目标只写一条日志。

## 五、界面

按 **J** 打开日志面板，小目标清单显示在日志正文上方：

```
小目标
  [完成] 储备饮水  5/5
  [ ] 带回医疗  0/2 —— 把 2 份绷带存进据点容器。
  [ ] 远途探索  12/55 —— 走到离据点 55 米以外的地方。
  [完成] 封住院子  1/1

- 第1天 08:00 [平静] 第1天清晨，在街区外醒来。
...
```

未完成的目标带一句做法说明，已完成的不再重复提示。清单不进地图、不进 HUD，避免变成常驻的催办条。

## 六、评估过但没做：背包空槽清理

做两天循环验收时发现，把背包里的东西吃到 0 之后，`inventory` 里那个键会保留为 0（读档后还会因为 JSON 变成 `0.0`）。曾尝试在数量归零时 `erase()`，但**回滚了**，原因有两条：

1. **会破坏守恒检查的类型稳定性。** `get(item, 0)` 在键存在且值为 `0.0` 时返回浮点，删键后返回整数 0；`tests/test_storage.gd` 用 `totals() == original` 做 200 轮随机存取的守恒断言，字典深度比较会把 `0` 与 `0.0` 判为不同，直接红了。
2. **实际影响比想象小。** 物品键名是 `rules.items` 里固定的 14 种，删了会复用同一个键，所以不会随游戏时长无限增长，最多留下十来个零值键。

结论：不值得为这点体积去动一个被 200 轮随机测试守着的事务路径。当前行为保留，记录在此。

## 七、验收

`tests/test_goals_v1.gd`（`GOALS_V1_OK`）：

1. 新档：schema 7、四个目标、无一完成、状态合法；日志面板文本含未完成项且不含「[完成]」。
2. 储备：背包里的水不算、存进柜子才算、达到 5 份后完成且只写一条日志。
3. 归属：2 瓶水存进别墅柜子**不会**让住宅据点的目标完成（3+2 正好跨过门槛，是真实的判别条件）；把据点改成别墅后同一批物资立刻算数。
4. 距离：短途不触发、记录跟随玩家、越过 55m 完成、回家不回退。
5. 工事：装好院子门后完成，且只报告一次。
6. 节流：连续多次推进不会重复写日志，`done` 里不会出现重复 id。
7. 迁移：schema 6 快照读入升到 7、目标全空；写着 7 却没有 `goals` 的快照被拒绝，`restore()` 会补齐。
8. 拒绝：未知 id、重复 id、负距离、超出世界的距离、超前的时间戳、`goals` 不是字典——六种非法状态全部拒绝。
9. 持久化：完成状态与距离记录读档后保留，读档不会重新播报。

`tests/test_two_day_loop.gd`（`TWO_DAY_LOOP_OK`）是路线图要求的连续两天验收，用一份存档走完：

准备（确认据点、门关着）→ 地图选点并抵达市集（触发发现）→ 搜刮（件数守恒，写出 `looted`）→ 遇敌挨打（`injured`）→ 脱离 → 回屋 → 吃喝治疗 → 存物资（每条 `stored` 对应一件）→ 手写一条日记 → 推进到夜间 → 床上睡到黎明 → **进入第 2 天**。

断言：`daily_summary` 恰好一条且 `summary_day == 1`；总结里的 `searches`、`stored`、`manual` 与实际行动一致；`rest_finished` 一条；存盘读档后位置、背包、容器、发现记录、目标进度全部一致。第二天再出门、回家、睡第二夜，进入第 3 天且 `daily_summary` 变成两条，读档状态仍然合法。

## 八、当前限制

- 目标只有四个且写死在世界数据里，没有按玩家进度动态生成，也没有难度或随机化。
- 完成目标没有任何实质回报（不给物资、不给属性），只有日志与面板上的状态。这是刻意的，但如果之后要加"完成度奖励"，必须先想清楚不能变成刷分。
- `distance` 采样只在 `advance_time()` 里做，玩家原地不动时不会更新；瞬移（读档、调试）不计入距离记录之外的任何判定。
- 目标不可放弃、不可隐藏、不可重置；新游戏才会清空。
- 「储备饮水」的阈值绑定住宅柜子+冰箱的初始 3 份。若之后调整初始物资，需要同步改 `goals.json` 的 `count`，否则目标可能一开局就自动完成——`test_goals_v1.gd` 里有一条断言专门守这个。
