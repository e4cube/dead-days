# 容器存取与物资存放闭环

2026-10-22。复用已有容器模型和 schema4 库存，增加双向逐件转移，不新增资产或存档迁移。

## 操作

靠近可触及的柜子或冰箱按 B，打开存取面板。每种物品提供“存入1件”“取回1件”，同时显示背包与容器数量、当前负重。没有物品、容器已空或取回后超重时，相应按钮禁用。B、Esc 或面板关闭按钮返回世界。E 继续执行原有批量搜刮。

按钮执行前重新检查目标容器身份、距离、所属建筑和墙体视线；过期目标不能远程操作。面板沿用现有背包/日志的世界暂停规则。死亡或睡眠状态不能存取。存入最后一件已装备武器后自动切回空手，取回后需手动装备。

库存事务在 Survival.transfer_item 中同时减少来源、增加目标，使用原物品重量和负重上限；拒绝请求不修改物品。模型仅负责事务，场景负责接近和遮挡。物资数量、门、时间、日志仍通过不可覆盖的快照保存；旧schema4快照可直接继续使用。

## 日志与限制

B存取分别产生 stored/retrieved 事件，包含实际容器、建筑、物品与数量，每日总结单独累计存入和取回。E仍属于搜刮转移统计，统计的是实际转移件数，不是物品唯一发现次数。

当前容器不模拟体积、物品分类或现实容量，只设存档安全计数上限10000件/类；背包仍有重量限制。没有拖拽、批量选择、丢弃到地面或实时多人访问。冰箱没有制冷、腐败或烹饪，家具外形沿用现有Blender/GLB资源。

## 验证

STORAGE_OK：固定种子的200次存入/取回操作，每次核对总物品守恒、负重及存档有效性；装备解除、精确存读档、超重原子拒绝、无效身份与日志拒绝、死亡/睡眠限制，以及每日总结分类计数。

住宅实际图形试玩：从街道进入厨房，在冰箱前按B，点击真实按钮存入木棍、确认立即解除装备及重量下降，关闭面板保存后继续，再取回同一木棍。同时验证面板暂停和过期目标拒绝。额外截图 work/house-storage.png。

完整运行与测试入口仍为 tools/run_checks.py --godot <路径> --blender <路径> --visual；原有12个GLB和Blender源工程继续包含在项目中。

本轮完整回归输出 STORAGE_OK 和 ALL_CHECKS_OK，正式存档与导出文件指纹未改变。扩展的暂停/过期目标测试和顶部负重、剩余提示即时刷新测试，在实际1920×1080窗口下得到 HOUSE_SLICE_OK。日志 work/storage-checks.log、storage-1080-checks.log、storage-ui-final.log；没有进行稳定帧率基准。
