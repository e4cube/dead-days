# 现有连通世界的玩法实施规划 V1

日期：2026-10-27。用户要求先看规划；本文件不代表已实现或已通过实机验收。本轮仅阅读代码与文档，没有重新运行新整图测试。

## 已核对的基线

- HEAD为2dc52c4，独立视觉切片分支。工厂、District、别墅、市集、操场及连通场景仍是未跟踪文件；rest.gd有未提交修改，全部保留。
- integrated_world.gd继承现有game.gd，挂接新资产，扩大导航网格，提供别墅楼梯、二层床和12个自定义搜刮点。
- 新搜刮点沿用model.loot、真实背包数量和重量规则；当前定义集中在脚本CUSTOM_DEFS中，建世界时追加规则和缺失容器状态。
- 默认启动入口仍为visual_slice_v1.tscn；连通世界需单独启动。当前整图测试覆盖局部碰撞、楼梯、导航路径和四处搜刮，不包含完整跨区存档往返验收。
- 原系统已有生存数值、昼夜、有限枪弹、近战、声音吸引、门损坏、休息、搬运及日志，继续复用。
- 人物、僵尸沿用本项目既有版本及其骨架、动作和外观分型，不接入DeepSeek另做的角色模型。场景资产可复用。

## 主循环

查看状态和物资缺口 → 在地图选择地点 → 准备武器与负重 → 外出探索与搜刮 → 避开或处理僵尸 → 将物资搬回据点 → 饮食、治疗、整理与休息 → 日志记录及次日计划。

地图暂不扩张。先让每个现有地点有用途，避免靠新增房屋推进内容量。

## 第一关：世界与存档统一

将区域、建筑、楼层、容器、床、边界和地点显示名放到共享世界配置，保留稳定ID。场景负责模型和碰撞，地图、交互、日志和存档读取同一地点数据。迁移采用增量版本，只有升级新增地点才补初始库存；当前版本容器缺失须作为错误处理，不能在每次建世界时自动补货。

核对整图边界与掉落物合法范围、读档落点恢复、二层高度、区域访问记录、灯光和休息安全。各区域分别拥有身份，避免把所有搜刮日志归为district_07。新世界与旧街区存档应明确世界标识和迁移方式，不能误读或覆盖玩家快照。

通过后将整图设为正式新游戏入口，保留旧场景供回归。

验收：同一存档走访市集、别墅两层、工厂，搜刮及放下物资，退出重进后位置、楼层、库存、容器耗尽和武器弹药一致；旧档迁移不复活敌人或补回旧物资。

## 第二关：物品栏与统一容器操作

背包先用清晰列表/格子展示真实持有物品，支持分类和选中详情，不优先开发复杂拖拽。

每项显示图标、名称、数量、单件重量、堆叠总重、用途；详情说明食物/水恢复量、药品治疗量与限制、武器伤害/范围/体力或弹药需求。枪械分开显示弹匣内弹数、容量和背包备用弹，不混算。

操作包括使用、装备、装填、卸弹、放下、取回和存入；提供1件/多件/尽可能取走，数量操作仍由模型统一校验重量和库存。操作不可用时显示实际原因。未实现耐久或品质的物品不显示虚假属性。

所有区域使用同一双栏容器面板：左侧容器、右侧背包，显示容量和剩余数量，满载时明确说明。沿用近距离与视线检查，二层物资不能从楼下隔空拿。保留快捷键和现有E操作的合理兼容。

验收：在新旧区域均可逐件和批量搬运，库存守恒，空柜无物资，负重限制生效；手枪与已装填弹药不会因放下/读档复制或消失。

## 第三关：统一地图

使用世界坐标生成2D地图，不制作另一张与场景脱节的装饰图。道路、建筑轮廓、区域、玩家位置/朝向统一映射。整图覆盖旧街区、District、市集、操场、别墅和工厂；支持平移、缩放、回到玩家及楼层选择。

地图固定北向，游戏镜头旋转时只调整玩家朝向，不旋转整张地图。首次进入逐步发现地点，支持已访问、已发现容器、上次查看时已空/未空、据点和玩家标记。容器状态是最近观察信息，不穿透显示未知库存；不显示实时敌人雷达。

手动标记可写短备注并保存；第一版指引显示目标方向和距离，不承诺跨楼层自动最短路线。全地图优先，小地图可在可读性验收后增加。M已用于静音，地图暂用Tab，设置中展示快捷键。

验收：在各区域入口和别墅上下层检查位置对应；地图缩放、不同游戏镜头朝向不偏移；发现进度与标记保存恢复；1080p和1152×720可读。

## 第四关：资源分工和局部风险

资源按地点用途分配：市集偏食物/水/包装物，住宅与别墅偏生活用品和少量医疗，工厂偏工具/零件，操场偏开放通行及少量应急物资。弹药和枪械只放在有依据的储藏点，调整当前钱箱、普通柜台等泛化投放，避免每处都产出全套补给。

按用户补充，整图必须显著增加僵尸，物资丰富地点附近配置更密集的尸群。敌人分布与地点用途、初始物资价值和可行走空间关联，采用固定ID及可复现的新游戏分布；不因玩家当前背包变多、打开地图或刚搜到物品而突然生成敌人。

第一轮调参候选为整图80—120只存活僵尸，不作为已验证承载量；先核查当前存档校验的100只上限，再按区域ID、存档大小、导航与实际帧耗时调整。工厂和市集约占总量55%—65%，别墅及普通住宅约20%—25%，余量布置在操场、道路与联络路；最终布点还需结合实际可玩面积，不按比例硬塞。起点留出观察与准备空间。

每个地点区分外围游荡、入口附近聚集及重点储藏点周边三层风险。高价值枪弹储藏点应有更明确的风险；开放道路保留可绕行的缺口。僵尸会受跑步、打击和枪声吸引，可能向清理区移动，因此地图标记只能表示上次观察情况，不能承诺永久安全。

继续复用本项目普通、工人、警员外观与AI。先实现可持续运行的分区模拟：近处保留完整感知、战斗与移动，远处降低更新频率或休眠，并保存位置、生命和死亡状态。休眠不等于删除后重新生成；追击中的敌人不能跨区突然消失。避免所有敌人每帧重算整图路径，检查门状态变化引起的导航重建成本。重点验证二层别墅与工厂夹层的追击能力；无法到达的楼层明确限制，不让睡眠规则默认其安全。

首版资源有限且不自动刷新，建立可重复的新游戏初始分布。完成步行、打击、枪击不同声音的用户听感调整；按需要接距离衰减，音频播放与AI噪声事件保持一致但不重复产生噪声。

验收：玩家能根据物资短缺选择不同目的地；枪弹真实消耗，空枪不能射击；市集与工厂比普通住宅明显更危险，尸群可观察、可吸引、可绕行或摆脱；搜空地点读档仍为空，死亡敌人不因加载复活。分别记录整图敌人总数、当前完整模拟数量、感知/寻路耗时和移动交战帧间隔；用最密集补给点交战及跨区往返验证，不能用住宅外静止FPS证明整图承载量。

## 第五关：据点与轻量加工

使用现有住宅或别墅建立一个明确据点：指定存储、床、照明及入口安全。先实现简易修门/加固、有限配方和基础烹饪，所需工具/原料可从现有区域取得。先统一楼层与门的归属，再允许新地点成为可靠睡眠点。

配方前置条件、时间与产出集中配置，操作中消耗时间并可能受危险打断；失败/取消不复制材料。首版不加入自由建筑、大型电网或复杂农业。

验收：外出获得材料 → 搬回 → 制作/修补 → 改善可验证的生存条件；一天的消耗和补给形成循环。

## 第六关：日志与持续游玩验收

将新地点发现、物资搬运、交战、危机和据点活动接入结构化事件，保留手写、心情、每日总结和Markdown导出。提供少量基于真实状态的小目标，例如储备饮水、带回医疗、完成一次远途探索，不伪造剧情或无限奖励。

验收以连续两天存档为准：准备出发 → 地图选点 → 新区域搜刮 → 遇敌撤退 → 回据点存物资 → 饮食/治疗 → 安全睡眠 → 次日继续。全程使用正式交互，录像或有序截图；自动测试另覆盖迁移、数量守恒、地图坐标与发现保存、枪弹消耗、上下层交互和睡眠安全。记录真实整图性能，尤其全图导航重建与远处场景渲染开销。

## 建议首个实施批次

首先完成第一至第三关：整图数据/存档稳定、物品栏和容器信息、统一地图及标记。以一次市集搜刮返回住宅的真实流程验收。紧接着实施第四关的整图增量尸群、高物资区高风险分布及分区模拟；只有完成这一步，才把大地图生存闭环视为首轮可玩成果。每一关单独验证和提交；当前规划不启动玩法代码修改，也不推送未验收成果。
