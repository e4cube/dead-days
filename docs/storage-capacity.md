# 容器承重与兼容旧物资

2026-10-22。继续使用schema4，不增加资产或复制库存。物品重量沿用原规则。

## 规则

| 容器 | 承重 |
|---|---:|
| 住宅柜 | 15kg |
| 诊所柜 | 5kg |
| 商店箱 | 20kg |
| 住宅冰箱 | 4kg |

规则在 rules.json 的 buildings[].storage_capacity、containers[].capacity；缺省由 storage_default_capacity=10kg 统一定义。数字为本街区的初始玩法平衡，不等同现实容器容积或结构强度。

Survival.container_weight 计算实际内容总重，container_capacity 读取规则。transfer_reason 同时提供界面按钮禁用原因与事务拒绝规则：存入不能超出容器承重，取回不能超出背包负重，空来源、无效物品、死亡、睡眠和数量安全上限继续检查。transfer_item 在修改任何数量前检查，失败不改变物品或生成存取事件。

按 B 打开存取面板可同时看到“背包 已用/上限”和“容器 已用/上限”。超重按钮禁用并有原因提示；即使直接触发按钮回调，模型仍再次拒绝。E批量搜刮仍按背包负重拿取，取出的物品会腾出容器空间。

## 旧存档

承重属于玩法规则，不重新定义既有物资是否合法。旧库存若超过新上限，快照仍可载入和保存，原数量完整保留；面板提示只可取出，直到有足够余量才接受新存入。不会截断库存、自动丢弃或改写旧文件。承重限制不会改变schema1/2/3到4的既有迁移流程。

## 验证

扩展 STORAGE_OK 测试：初始库存均容纳、200次随机存取继续守恒且不超容器承重、用小重量绷带精确填满4kg、拒绝再存入且库存/事件不变、超限旧快照载入保持数量与原文件字节、取出后恢复存入。

实际住宅试玩通过按钮把冰箱装到3.9/4.0kg，背包仍有饮水却不能再存入；手动触发禁用按钮也被模型拒绝，保存继续后完整恢复。截图 work/house-storage-full.png；使用已有真实输入路线到达冰箱，没有传送。

仍不模拟物品体积、堆叠格子、容器类型限制、温度或腐败；例如木棍也可以暂存在冰箱。12个Blender/GLB资产继续沿用并参与重生成检查。

本轮完整检查输出 STORAGE_OK、HOUSE_SLICE_OK、ALL_CHECKS_OK；角色/僵尸/生存/过夜/迁移及资产重生成回归通过，正式存档与导出文件指纹未变。另以1920×1080执行实际存取试玩通过。日志 work/capacity-checks.log、capacity-1080.log；未做稳定帧率基准。
