# 生存循环 V1：流畅、可读、能跑完一趟远途（2026-10-27）

本文件对应「先保证流畅和可读，再完善生存循环」的**第一阶段收尾**。五项交付：
性能基线、画质档位、物品栏、地图、以及一次真正打完的远途搜刮。性能数字的完整
记录在 `docs/performance-baseline-v1.md`，这里只留结论和这一阶段新增的东西。

## 1. 性能基线（摘要）

`godot/tests/perf_baseline.gd` + `tools/perf_baseline.py`。关 VSync、每场景独立进程、
每条件重复 3 次取中位数。环境：GTX 1650 / 1920×1080 / Godot 4.7.2 GL Compatibility。

| 场景 | 优化前 | 优化后（中位） |
| --- | --- | --- |
| home_indoor | 87 | 86.31 |
| market | 62 | 65.56 |
| factory | 74 | 76.66 |
| horde_chase | **31** | **64.32** |
| gunshot | **35** | **69.91** |

优化集中在三处，都不改模拟规则：

- **导航重建**：原来每次开门全图扫描（280×168 格 × 300+ 碰撞源 ≈ 1400 万次比较），
  改成按矩形光栅化；开关门只修补门洞周围（`navigation.patch()`）。
- **A\* 预算**：`PATH_BUDGET = 8` 次/物理帧，超出的调用返回空路径，调用方保留上一条路线。
  枪声同帧唤醒几十只时不会再顶穿帧预算。
- **HUD/交互分频**：`refresh_hud()` 按帧节流且只在文本变化时写 Label；
  `nearby()`/`closest_bed()` 走 120 ms 缓存（玩家移动 >0.25 m 失效），权威动作仍走原函数。

## 5. 一次有敌人的远途搜刮

`godot/tests/test_connected_expedition.gd`（`CONNECTED_EXPEDITION_OK`）：

1. 住宅搜柜子、拿木棍、装备；
2. 沿主街向东，路过**诊所拿绷带**（路上战斗多于一条血的容量，真实玩家会这么做）；
3. 进入市集，应答追击的僵尸（近战击杀，写进日志）；
4. 穿过货架区到西侧摊位搜刮，观察记录写入地图；
5. 原路回城、`B` 存入据点、确认负重归零；
6. `F5` 存档 → 继续，校验位置、背包、发现区域、击杀数、死亡僵尸、观察记录、
   以及「已搜刮的库存不会在读档后刷新」。

终局：**17  kills，回城 79 血**，全部断言通过。

跑法（headless，固定步长，几分钟内完成）：

```
D:/GameDev/Godot_v4.7.2-stable_win64.exe --headless --fixed-fps 60 --path godot \
  --script res://tests/test_connected_expedition.gd
```

### 为了让这一趟能走完，改了什么

| 改动 | 原因（实测） |
| --- | --- |
| 近战噪音：拳头 2.5 m / 木棍 4.5 m（原统一走 `combat.noise_radius = 12`） | 挥一棍就把 12 m 内整片区域拖过来，市集里永远打不完。枪仍是 32 m。 |
| 僵尸单次伤害 10 → 6 | 每次单杀固定掉一次血（10），单程到市集要 15+ 杀，血池 100+3×25=175，**必死**。改 6 后同样路线约 100，留出回程余量。 |

两项都是单值改动，完整平衡（密度、武器曲线、昼夜）留给第三阶段「尸群与区域平衡」。

### 这一趟暴露的关卡缺陷（下一步要修）

1. **别墅厨房柜搜不到**：`navigation.nearest()` 在柜子 ±2 格内找不到任何可站格，
   而可达的西侧过道最近点距柜 2.37 m > 交互半径 1.65 m。等于这个柜子**在实机里
   永远打不开**。东侧卧室（`villa_wardrobe` / `villa_bedside`）也被隔断与净空余量
   （0.32 m）挤死，导航会把人绕到房子外面去。
   → 要么给隔断留出真正的门洞宽度，要么给容器配「交互站位点」而不是拿柜子坐标当站位。
2. **市集/工厂是网格化密排**（24 只 / 28 只），站定搜刮必然被围死。当前只能靠
   「打了就走」穿过，货架区的深度收益和风险不成比例。这是第三阶段的主要工作。
3. 主街 x≈7 处经常有僵尸长时间站在通道中央（`connector` 巡逻点与路口重叠），
   玩家会被顶着走不动，需要给巡逻/游荡加一点「不要长时间停在路中央」的偏好。

## 6. 收尾修复：捡走最后一件后地面标记不消失

`test_ground_drop_playthrough` 在收尾回归里挂着一条失败（`E recovers remaining stock
and hides empty marker`）。查下来是**表现层的时序漏洞**，不是存档/容器逻辑错：

- `E` 捡走整堆后，地面上的 `loot_crate` 模型最多要 250 ms 才消失；
- `refresh_hud()` 有两道节流：`hud_interval`（100/150/70 ms，随画质档位）和
  `LINK_INTERVAL_MS = 250`（地面掉落、商店、诊所这类「世界物件 ↔ 库存」的同步）；
- `force=true` 当初只绕过了第一道，**没有绕过第二道**，而 `interact()` 结尾调的正是
  `refresh_hud(true)`——于是「刚捡完」这一刻的语义上的强刷新被丢掉了。

修复一行（`scripts/game.gd:788`）：

```gdscript
if force or paused or now - int(link_stamp) >= LINK_INTERVAL_MS:
```

`force` 的语义就是「立刻刷新」，三个调用点（交互、切画质、设据点）都是单次事件，
不进每帧路径，所以不会把 `GroundVisual.update` 的调用频率抬上去。

回归结果：`test_ground_drop_playthrough` 由 FAIL 转 **OK**；`godot/tests/` 下
**41 个 GDScript 测试全绿**（含 `CONNECTED_EXPEDITION_OK`）。
