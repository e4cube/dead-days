# 据点建设与轻量制作 V1

路线图第五关的落地版本。核心变化是：**据点是一个地点，不再等价于"一扇能关的门"**。此前只有 `rules.buildings` 里的街道住宅可被 G 键标记，别墅、工厂、市集虽然能走进去，却既不能设为据点，也不能算"在家里做东西"。这一版把可居住空间统一成 `zones()`，并把据点从"标记"推进为"能改善生存条件的工作场所"。

## 据点归属

`survival.gd/zones()` 从 `rules.buildings` 派生街道建筑的室内矩形（沿用 `rest.gd` 的 `room` 口径：半宽 2.45、进深到 `max_z -0.4`、`|y| < 0.5`）；`connected_model.gd` 覆盖它，追加 `connected_world.json/base_zones` 里的三处室内：

| 地点 | 范围 | y 区间 |
| --- | --- | --- |
| 别墅 villa_07 | [109.65, -26.35, 12.7, 8.7] | -0.5 ~ 6.7 |
| 市集 market_07 | [51.4, -27.0, 31.2, 25.0] | -0.5 ~ 1.8 |
| 工厂 factory_07 | [152.95, 15.25, 25.1, 14.2] | -0.5 ~ 4.4 |

别墅的 y 区间覆盖两层，所以二层卧室与一层厨房属于同一个据点，不会因为上楼就变成"不在家"。`base_at(position)` 返回所在地点 ID，`in_base()` 用它和 `base_id()` 比对；G 键改为取 `base_at(player.position)`，不再遍历门列表。据点 ID 存在 `state.exploration.base`（连通世界）或 `state.base`（旧街区场景），旧档缺字段时回落 `home`。

`set_base` 只接受 `zones()` 里的 ID，写一条 `base_set` 事件。未知地点直接拒绝，不会把据点设成一个走不进去的名字。

## 门工事

`rules.json/door_build` 集中配置：`reinforce_step = 50`、`reinforce_limit = 2`。`door_damage.gd` 增加每扇门独立的上限：

- `max_health(model, id)` = `door_damage.health`(120) + `door_level[id] × 50`
- `level(model, id)` 读 `state.door_level`，默认 0
- 上限是**按门**保存的，不是全局倍率。加固过的入口读档后仍然加固，没碰过的门保持 120。

两条操作都由配方驱动（走 `crafting.gd`，不是即时按钮）：

- **修门**：2 木板 + 锤子，20 分钟。把耐久补回当前上限。破门（耐久 0）也能修，但修好后门板恢复到"开着"状态，玩家必须再按 E 关门——修复不会顺手给一个安全屋。
- **加固**：3 木板 + 1 废金属 + 锤子，45 分钟。层数 +1，上限 +50，**当前耐久也同步 +50**（不是补满），所以加固不能当廉价修复用。破门状态下拒绝加固，必须先修。

`DoorDamage.valid` 从"统一按 120 校验"改为按每扇门的实际上限校验，并校验 `door_level` 落在 0~上限层数之间；`door_health` 仍要求破门必须处于开放状态。

## 配方与消耗

配方集中在 `godot/data/crafting.json`，四条：

| 配方 | 前置 | 材料 | 耗时 | 产出 |
| --- | --- | --- | --- | --- |
| 修门 | 站在门 1.65 米内，门有损伤 | 木板×2 | 20 分钟 | 耐久回到上限 |
| 加固门 | 站在门旁，门未破且有层数余量 | 木板×3、废金属×1 | 45 分钟 | 上限 +50 |
| 烹饪热餐 | 在据点内 | 罐头×1、饮用水×1 | 15 分钟 | 热餐×1（饱腹 +55） |
| 裁制绷带 | 在据点内 | 布条×2 | 10 分钟 | 绷带×1 |

规则要点：

1. **材料在开始时扣除**，记入 `state.craft.spent`。取消、危险打断、读档后放弃都由同一个 `cancel()` 退还，且只退一次，所以既不会复制也不会吞材料。
2. **耗时是真实推进的游戏时间**，走 `advance_time`，与饥饿、口渴、僵尸移动同一时钟。制作时玩家不能移动，制作 20 分钟约等于 10 秒实时（`minutes_per_second = 2.0`）。
3. **危险判定统一**：`crafting.json/danger_radius = 3.0`。开工前和每一帧用同一个函数，所以"按钮点得下去但立刻被打断"不会发生；僵尸进入 3 米或处于追击/搜索且目标在 3 米内即中断。
4. **距离在模型层校验**，不只靠 UI。`reason()` 自己算玩家到门的平面距离，超过 `interaction_range` 就返回"需要站到门旁"，所以脚本或面板漏洞不能远程修门。
5. **负重前置检查**：产出的净重量会让背包超限时直接拒绝，避免"做完了东西掉地上"的模糊结果。

新增物品：木板 1.0kg / 废金属 0.8kg / 布条 0.15kg / 锤子 0.9kg（`kind: tool`，不消耗）/ 热餐 0.7kg。一组加固材料（3 木板 + 1 金属 + 锤子）合计 4.7kg，刚好放进 5.0kg 的背包，不需要为了做一件事反复搬运。材料与工具都带 `kind`，`use_item` 对它们直接返回 false，不会再走"恢复数值"分支导致空键崩溃。

## 材料来源

`connected_world.json` 修订号 3 → 4，新增三个容器（`introduced_revision: 4`）：

- 工厂工作台 `factory_workbench` [161.0, 1.0, 18.4]：锤子×1、木板×2、废金属×2
- 别墅工具棚 `villa_shed` [110.8, 1.0, -21.0]：木板×3、布条×2
- 市集布摊 `market_fabric` [57.5, 1.0, -21.5]：布条×4、木板×1

三个位置都选在已确认可通行的室内空地上（工厂工作台在冲压机与传送带之间的通道，别墅工具棚避开北墙一排柜子，市集布摊在两排摊位中间）。容器模型复用现有 GLB（`table` / `cabinet` / `loot_crate`），并**不挂碰撞体**——新碰撞会改变导航网格和已验证的动线，而这批道具只是视觉参照。没有模型的新容器只有悬空标签，这一版选择让道具看得见、走位不变。

旧档通过 `expand_world_state()` 只补这三个**新增**容器；已存在容器里的库存不会被追加，符合"升级不补回旧物资"的既有原则。

## 存档

schema 4 → 5。新增 `state.craft` 与 `state.door_level`，由 `add_base_state()` 统一初始化，接在既有的 1→2→3→4 迁移链后面（`schema == 4` 分支自动继续到 5）。

`valid_craft()` 校验：

- `craft` 必须是字典，`active` 是 bool，`recipe`/`door` 是字符串，`spent` 是合法物品表
- `door_level` 的每个 ID 必须存在于 `doors`，层数在 0~`reinforce_limit`
- 进行中时：配方必须存在，`minutes_left` 落在 (0, 配置耗时] 内；门类配方要求 `door` 是已知门
- 空闲时：`recipe`/`door` 必须为空，`minutes_left` 为 0，`spent` 为空

顺带修正一处硬编码：容器存在性检查原本写死 `candidate.schema == 4`，升到 5 后会让新容器的缺失校验静默失效，已改为 `>= 4`。

## 操作

| 键 | 行为 |
| --- | --- |
| G | 在任意可居住室内设据点（别墅/工厂/市集同样有效） |
| C | 打开"据点工事与制作"面板 |
| 移动 / 空格 | 制作中停手，材料退还 |
| Esc | 关闭面板 |

面板按上下文分区：附近有门显示门名、耐久、加固层数与"修门/加固"两条配方；在据点内显示烹饪与绷带。不满足条件的配方保留在列表里并写明原因（"材料不足：木板 1/2"、"缺少工具：锤子"、"只能在据点内制作"），不隐藏也不假装可用。制作完成自动保存，并写一条 `crafted` / `door_repaired` / `door_reinforced` 事件；中断写 `craft_interrupted` 并记录退还材料。

HUD 在门旁追加 `[C] 修门/加固` 与实时耐久（读 `max_health` 而不是固定 120），在据点内追加 `[C] 据点制作`，制作中替换为进度与"移动或空格停手"。

## 验证

`godot/tests/test_base_v1.gd` 覆盖：

- 据点归属：街道室内 / 街上空地 / 别墅一层 / 别墅二层 / 工厂，以及 villa ↔ home 切换后 `in_base()` 的结果
- 门工事：上限来自规则、修门只补到当前上限、部分进度不改耐久、加固提升上限与当前值、第二层、达到上限后拒绝、破门必须先修、修好仍开着、手动关门后恢复
- 配方：烹饪材料前置扣除、进行中拒绝第二条、取消全额退还且只退一次、完成产出热餐并可食用、绷带配方精确消耗 2 布条
- 打断：僵尸进入半径、`danger()` 与 `reason()` 口径一致、中断退还材料并写日志、清空威胁后恢复可用
- 护栏：据点外不能烹饪、街对面不能修门、站在门旁可以、缺料与缺工具的原因文案精确、完好门不需要修
- 存档：加固后存读档保持层数与上限、制作中存档合法、读档后制作继续并正常产出、不复制材料

## 限制

- 没有自由建造、电网、农业、家具摆放；能做的只有这四条配方。
- **门工事只对街道建筑有效**：别墅/工厂/市集是用 `structures` 描述的开放室内，没有门对象，所以把据点设在别墅时没有可修可加固的入口。给这些地点补入口防御需要先给 `structures` 加门，属于后续工作。
- 没有制作动画、工作台模型细节或音效；制作期间角色保持站立。
- 工具没有耐久，锤子永不损坏；配方也没有失败概率，只有"被危险打断"这一种失败。
- 未做长时平衡验证：一天内能搬回多少材料、加固两层是否过于便宜，需要实际试玩判断，本版不宣称数值已平衡。
