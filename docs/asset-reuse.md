# 当前开发资产的跨项目复用评估

结论：有明确的复用机会。当前更适合作为自有项目的基础资产库与制作管线，还不是可直接出售或公开分发的成熟通用素材包。画质未通过全部产品级门禁，不能把文件可导入等同于美术质量合格。

## 可复用范围

|资产|目前可带走什么|迁移时要补什么|
|--|--|--|
|床、柜、桌、门、箱、汽车、树木、路灯、围栏等独立GLB|网格、UV、嵌入式材质与贴图；对应 `.blend` 可编辑|目标引擎内重新设置碰撞、交互、LOD及材质亮度；门原点在铰链处|
|玩家、僵尸|16骨骼蒙皮，玩家六动作、僵尸五动作，嵌入式材质|动作控制器、武器挂接、碰撞和战斗逻辑；不是通用Humanoid标准骨架，跨骨架重定向未验证|
|三类建筑|实体结构及命名过的屋顶/墙体节点|适配目标项目的进屋检测与剖切规则；可见性不会随GLB自动变化|
|住宅、诊所、商店细节套件|整套房间家具及局部坐标|当前以建筑细节集合导出，沙发、冰箱等尚非独立标准化物件；应从源工程拆出、设原点再单独导出|
|PBR材质库与原创表面图|集中JSON配方、512px颜色/粗糙度/法线图、共享变体规则|Godot运行时三平面映射不是GLB标准；GLB自带UV版本可独立加载，但不同引擎的观感仍需校准|
|Blender生成器|可编辑参数、米制比例、GLB导出、可重复生成检查|目前读取仓库固定目录、共享helper及JSON，不能只复制一个脚本；先连同依赖运行，再整理成独立包|
|库存、事件、日志、存档等代码|规则数据和已有验证思路|`game.gd`及各建筑接入层仍有项目耦合，宜提取纯规则后接入新项目；不能把复制场景当成完成迁移|

## 已验证与未验证

僵尸分型增量：`zombie.glb` 现在含普通、工人、警员的服装附件节点，仍只有一套骨架。其他项目导入后需按 `DD_Variant_<id>_Outfit` 选择一个；本项目的 `zombie_appearance.gd` 已负责互斥显隐。单文件能导入不代表默认显示全部服装是正确效果。

执行 `tools/audit_asset_reuse.py` 检查全部21份GLB的glTF 2.0容器、源工程存在性、SHA及外部buffer/image路径。当前全部贴图和几何自包含，不需要源项目绝对路径。报告位于 `work/visual-slice/asset-reuse-audit.json`。

带 `--godot` 时，只将21份GLB复制到隔离目录 `work/asset-reuse-project/`，不复制游戏脚本、规则、材质JSON或存档；由Godot重新导入并逐个实例化、确认网格存在。原始导入记录在 `asset-reuse-import.log`。这证明模型层可脱离游戏代码加载，不证明碰撞、AI或互动也自动迁移。

未进行 Unity、Unreal、Three.js 的实际导入或视觉测试；也未验证GLB导入Blender后完整往返。不能把格式支持推断为这些工具中的实测通过。当前Godot实机场景验收仍见 `visual-slice-v1-report.md`。

## 来源与分发边界

- 当前21份模型与程序表面图由项目生成脚本制作，资产来源记录在 `art/source/visual-slice-v1-manifest.json`。没有把参考游戏的模型或截图做成运行材质。
- `art/references/` 是用户提供的视觉研究资料，包含第三方游戏/社交平台截图与用户标记为AI生成的定妆照；不作为可复用游戏素材打包。
- 现有外部地面图独立记录在 `art-library/index/LICENSE_LEDGER.md`，当前为审核通过的 Poly Haven CC0 条目。迁移该条目时连同元数据、证据与原始来源记录保存；不要把整个素材搜索库视为已获准资产。
- 仓库当前没有根目录 `LICENSE` 文件。这里没有替项目所有者授予第三方使用权，也没有替你选择开源或商业素材包许可；对外分发前需明确项目代码、原创资源和第三方条目的各自授权说明。GLB自包含不等于授权自动成立。

## 建议的最小整理顺序

先整理独立静态道具，再拆分住宅家具，最后处理角色重定向与玩法模块。每个可复用资产保留：稳定ID、米制尺寸、原点/朝向、源工程、GLB、材质来源、碰撞建议和预览；保留来源清单但排除参考截图、用户存档及测试缓存。当前不额外创建整套素材包，以免打断游戏美术迭代。

```powershell
python tools/audit_asset_reuse.py --godot D:\GameDev\Godot_v4.7.2-stable_win64.exe
```
