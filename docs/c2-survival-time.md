# 阶段 C2：时钟、休息与第二天（2026-10-21）

## 统一时间与生存规则

`survival_time.gd` 按游戏分钟管理生理和日界线；`rest.gd` 管理休息资格、计划、取消与完成，均独立于场景绘制。数值集中在 `rules.json` 的time/survival/rest/beds/room字段。

新档从第1天08:00开始（C1原始时钟冻结在06:00；旧档保留原时间）。每模拟秒推进2游戏分钟，一天为12现实分钟。饱腹每游戏分钟减0.025，水分减0.035；休息代谢为0.7倍。耗尽后才分别以每游戏分钟0.25/0.4点生命损伤，不能靠受击保护免疫饥渴。阈值跨越、耗尽、濒死和死亡记录真实事件；死亡后时钟停止。

充分饱食且有水时，休息每游戏分钟恢复0.02生命；营养不足不产生凭空回血。体力按模拟秒恢复，消耗品仍由真实库存支付。不是完整营养学/感染模拟。

光照以06:00→08:00渐亮、18:00→20:00渐暗，白天和夜晚分别改变DirectionalLight3D能量、颜色、角度及环境光；不增加重型后处理。夜间感知范围按光照渐变降至白天0.65倍，仍做墙体射线遮挡。

## 床与资格

住宅内有有碰撞的床，位置/尺寸/使用半径由数据定义。床和角色可达空间加入相同导航障碍。靠近床：R休息1小时；夜间18:00后或凌晨06:00前，T睡到最近黎明。白天T不会跳到明天，提示先短休。T、R、移动或攻击意图可主动起身；移动/攻击下一物理帧才按正常速度执行。

开始和每个加速步前后检查：

- 玩家存活，处于床的使用半径内，并真正位于对应房屋内部；不能站屋外隔墙休息。
- 本屋门关闭。
- 没有活僵尸在5m内（即使墙体挡住也保守拒绝）。
- 没有警觉/追击/搜索中的僵尸，其最后目标位于5m内。不能靠远处仍在追击而直接休息跳时。

这是一套明确而保守的安全规则。门尚不可破坏，不宣称具备最终游戏的围攻平衡。

## 世界持续推进，不跳过威胁

休息把当前帧的模拟预算提高到60倍，每步最多0.05模拟秒、每帧最多32步，预算受限以保护界面响应。每个步同时推进生存时钟、饥渴/回血、声音寿命、战斗计时及每只僵尸感知/记忆/移动/攻击；不是把minutes直接改成次日。

`move_and_slide` 内部使用引擎物理帧dt，不能直接拿来多次模拟自定义休息dt。因此僵尸改用显式velocity×step的move_and_collide扫掠和最多3次滑动；地面/墙/门/玩家碰撞始终保留。初始相交的僵尸在分离扫掠时临时忽略彼此，避免重合卡死，环境碰撞不关闭。C1绕墙/关门/群体分离回归继续通过。

危险实际接近时停止当前计划，仅保留已经经过的时间和消耗，产生sleep_danger；门被打开或身体无法继续时也终止。用户可暂停日志查看；整个世界一起暂停。停止休息后不会补跑被取消的剩余预算。

休息正常完成后记录真实结束事件，自动保存新快照；失败不删除旧快照。睡眠和短休过程中不能同时使用物品或攻击。

## 日界线与日志

跨午夜逐段处理，保留溢出分钟。`calendar.last_summary_day`避免读档、重复刷新或同日重复总结。

每日总结从该日已有结构化事件统计进入建筑、实际获得物品件数、搜刮次数、击杀、实际受伤点数、消耗品使用与手写记录。零次就写零次，不随机添加“险些死亡”等故事。总结在次日00:00记录，睡到06:00另记录醒来事件；二者都能导出Markdown。

## 存档 schema 3

保留C1的敌人/声音/装备，并新增calendar和rest（active、kind、bed、开始绝对分钟、目标绝对分钟）。目标用绝对游戏分钟，可跨午夜恢复，不会读档后重新睡一整夜。

schema1先迁移敌人字段，再加时钟/休息；schema2只添加时钟/休息，原有敌人位置和状态不变。所有迁移只在内存进行，源文件字节不改，后续仍保存为新快照。未知schema、损坏日标记、过期或错误休息目标、会破坏汇总的事件payload在加载前拒绝。

实际目录仍为 `%APPDATA%/DeadDaysRebuild/`；测试只写tests子目录。

## 验证与限制

- TIME_RULES_OK：统一换算、代谢、跨日分段、有营养休息的分步一致性、实际耗尽后伤害、死亡与低营养、真实事件统计/去重、床/门/室内/敌人资格、活跃休息往返、schema2只读迁移、坏目标/payload拒绝。
- REST_SAFETY_OK：原安全地点的游荡僵尸真实移动靠近，在到黎明前中断；不能立即再次睡走威胁；门改变先停再推进；日志暂停和主动起身。
- SLEEP_PLAYTHROUGH_OK：默认街区和敌人，从菜单以Input进入房屋、关门、搜刮/使用、走到床、短休到夜间、实际灯光变暗、僵尸继续巡逻、睡眠中F5/Esc/继续、次日06:00、真实需要消耗与每日总结、Markdown导出、次日存读档。过程无传送，无直接赋值时钟。
- 老版存档哨兵、Godot规则、GLB、僵尸物理、搜刮与追击脱离回归同一入口运行；正式旧版和Godot存档/导出哈希前后比较。
